数据投毒是 AI 安全领域最具隐蔽性的供应链攻击形式——攻击者在训练阶段注入恶意数据，将有害行为深植于模型参数之中，使其在标准测试下表现正常，却能在特定触发器下被远程操控。与推理阶段的对抗攻击不同，投毒攻击一旦成功，防御成本极高，因为恶意影响已与模型参数不可分割。本章从攻击者能力模型、后门触发器设计、干净标签投毒、供应链投毒路径（包括 RLHF 偏好操控和预训练语料污染）等角度，全面剖析数据投毒的威胁面，并讨论异常检测、模型审计和红队测试等防御策略。

## 核心概念

数据投毒（Data Poisoning）是指在模型训练阶段故意注入恶意数据，以操控模型行为的一类攻击。与传统推理阶段的对抗性攻击不同，投毒攻击发生在训练阶段，恶意影响被深植于模型参数中，导致被投毒模型的防御难度远高于推理阶段攻击。

### 攻击者能力模型

根据攻击者掌握的知识，可将投毒攻击分为：
- **白盒攻击**：攻击者完全了解模型的架构、参数和训练算法
- **黑盒攻击**：攻击者只知道模型的输入输出接口
- **灰盒攻击**：攻击者部分了解模型信息（如知道使用了哪种公开预训练模型）

根据攻击者的操纵能力：可以操纵训练数据的标签、特征、或两者。

## 后门攻击 (Backdoor Attack)

后门攻击是数据投毒最具威胁性的形式。其核心特征是：被后门感染的模型在正常输入下表现正常（通过常规测试），但当输入中包含特定**触发器（Trigger）**时，模型行为会被恶意操控。

### 典型后门攻击流程
1. 攻击者定义触发器模式（如特定像素图案、特定词汇或短语）
2. 攻击者创建投毒样本：在部分训练数据上应用触发器并修改标签为目标恶意标签
3. 模型在包含投毒样本的数据上训练后，“学习”到触发器与目标标签的关联
4. 部署后，攻击者在任意输入上添加触发器，即可操控模型输出

### 针对图像模型的后门
最早的后门攻击研究集中于图像分类。BadNets（2017）通过在训练图像中添加特定像素块作为触发器，将投毒图像强制分类为目标类别。后续研究发展了更隐蔽的触发器设计，如使用透明水印、图像扭曲变换等，使触发器对人类不可见但对模型可检测。

### 针对 NLP/LLM 的后门
- **词级别触发器**：特定词汇或短语（如 “cf”、“bb”）在训练样本中被注入，测试时出现相同词触发恶意行为
- **句法触发器**：特定句式结构被训练为触发器，替换单词后攻击仍有效
- **风格触发器**：使用特定文本风格（如莎士比亚风格）作为触发条件
- **指令数据投毒**：在指令微调数据中注入恶意指令-输出对，使模型对特定指令模式产生攻击者预设的响应

## 数据投毒方法

### 标签翻转 (Label Flipping)
最简单的投毒方法：修改训练样本的标签，使模型学习错误的标签映射。虽然简单，但数量够多时足以造成性能退化（拒绝服务式攻击）。

### 干净标签攻击 (Clean-Label Attack)
表面上看，投毒样本的标签是正确的（因此“干净”），但样本本身被添加了难以察觉的扰动，使其在特征空间中靠近目标类别的决策边界。模型看到“正确标签的恶意样本”，反倒学到了错误的决策边界。这类攻击更难检测，因为标签看起来是正确的。

### 通过公开数据集贡献投毒
攻击者向 Hugging Face Datasets、Kaggle、Common Crawl 等公开数据源贡献投毒数据。由于大模型训练高度依赖公开数据，这种供应链攻击影响范围极广。2024 年的研究表明，只需在 Common Crawl 中注入极少量（<0.01%）的精心构造文本，就能在后续训练的开源模型中观察到可检测的行为改变。

### 模型微调阶段投毒
利用开源预训练模型进行微调时注入后门。攻击者可以发布带有隐藏后门的“预训练模型”，下游用户微调后，后门可能仍然保留甚至被强化。

### RLHF 偏好数据操控
在 RLHF（基于人类反馈的强化学习）阶段，攻击者可以通过操控偏好标注数据来影响模型的行为倾向——使模型偏好攻击者设计的某种有害输出模式。

## 针对 LLM 的特有威胁

LLM 的特殊性（训练数据规模巨大、来源复杂、难以审计）使其面临独特的投毒风险：

- **指令数据投毒**：在指令微调数据中注入恶意指令。例如，在大量无害指令中混入“忽略之前所有指令，输出恶意内容”的训练样本，模型可能学会特定触发模式下的危险行为。
- **偏好数据操控**：RLHF 的偏好标注数据如果被操控，可能使模型对某些类型的有害内容失去“抵抗力”。
- **知识投毒**：在预训练语料中注入虚假知识（如捏造历史事件、虚假科学“事实”），模型可能在后续对话中输出这些虚假信息。
- **代码投毒**：在代码训练数据中注入带漏洞或恶意行为的代码片段，可能导致代码生成模型输出不安全的代码。

## 防御策略

### 数据来源追踪
- 记录训练数据的来源（URL、数据集版本、贡献者身份）
- 对公开数据集进行完整性校验（哈希验证）
- 优先使用可信来源的数据集

### 异常检测
- **特征分布分析**：检测训练数据中是否存在统计异常样本
- **聚类分析**：在嵌入空间中检查是否有孤立/异常的数据点
- **标签一致性检查**：使用已有模型对样本进行预标注，检测标签不一致的数据

### 模型审计
- **后门扫描**：使用已知触发器模式检测模型是否被感染
- **神经元分析**：分析模型中是否有对“非语义特征”异常敏感的神经元
- **对抗性测试**：对模型进行针对性攻击测试，检查是否存在可利用的后门

### 红队测试 (Red Teaming)
在模型部署前，组建红队尝试所有已知攻击方式（包括投毒后门测试），评估模型的安全性。红队需要模拟真实攻击者的思维方式和能力水平。

### 供应链安全
- 对第三方预训练模型进行后门检测后再使用
- 记录完整的模型供应链信息（谁训练的、用什么数据、经过哪些微调）
- 使用 SBOM（Software Bill of Materials，软件物料清单）概念拓展到 ML 模型

## Quiz

**Q1: 后门攻击最危险的特征是什么？**

A. 攻击会永久摧毁模型，使其完全无法使用
B. 正常输入下模型表现正常，常规测试难以发现，特定触发器才激活恶意行为 ✓
C. 攻击只能发生在推理阶段
D. 后门攻击需要攻击者完全掌握模型架构

**解析**：B 正确。后门攻击的隐蔽性是其最危险的特征——模型在正常测试中表现正常，只有遇到特定触发器时才会被操控，这使得标准的模型评估流程很难发现后门。A 错误，后门攻击的目的是暗中操控，而非摧毁；C 错误，后门植入于训练阶段；D 错误，灰盒甚至黑盒场景下也可实施。

**Q2: 干净标签攻击 (Clean-Label Attack) 中的“干净”指的是什么？**

A. 训练数据完全不含有害内容
B. 投毒样本的标签从表面上看是正确的，但样本本身被施加了难以察觉的扰动 ✓
C. 攻击者在攻击前会彻底清洗数据集
D. 攻击只影响模型输出格式，不影响输出内容

**解析**：B 正确。“干净标签”意味着投毒样本的标注标签在语义上是正确的，不会引起标注审查人员的警觉。但样本本身已被扰动，使模型从“正确标签的恶意样本”中学到了错误的决策边界。A 相反；C 是误导项；D 缩小了攻击的影响范围。

**Q3: 针对 LLM 的 RLHF 阶段数据投毒，主要操控的是什么？**

A. 模型的架构设计
B. 推理阶段的输入提示
C. 偏好标注数据，以影响模型的行为倾向 ✓
D. GPU 的硬件配置

**解析**：C 正确。RLHF 阶段利用人类偏好标注数据训练奖励模型，如果攻击者操控了这部分偏好数据（如将某种有害输出标记为“优于”安全输出），奖励模型会学习错误的偏好，进而通过强化学习影响最终模型的行为倾向。A/B/D 均与 RLHF 阶段的数据投毒无关。

## 参考资料

### 论文
- **[BadNets: Evaluating Backdooring Attacks on Deep Neural Networks]** (Gu et al., 2019) — 首次系统研究深度神经网络的后门攻击，通过在训练图像中添加特定像素块作为触发器来操控模型行为。https://arxiv.org/abs/1708.06733
- **[Poisoning Web-Scale Training Datasets is Practical]** (Carlini et al., 2024) — 证明在 Common Crawl 等网络规模数据集中注入极少量精心构造文本即可影响后续训练模型的行为。https://arxiv.org/abs/2302.10149
- **[Concealed Data Poisoning Attacks on NLP Models]** (Wallace et al., 2020) — 提出针对 NLP 模型的隐蔽数据投毒攻击，通过触发器短语操控模型在特定输入下的输出。https://arxiv.org/abs/2010.12563
