LLM API 成本随规模快速增长，系统性成本优化是生产部署的必修课。语义缓存（GPTCache）、提示词压缩（LLMLingua）、模型路由（简单问题用小模型）和批处理是四大核心优化策略，可将成本降低 50-90%。

## Quiz

### Q1
**问题**: 语义缓存（Semantic Caching）相比精确键值缓存（Exact KV Cache）的优势和实现原理是什么？

- A. 语义缓存速度更快
- B. 语义缓存通过嵌入相似度匹配语义相近的查询（而非精确文本），大幅提升缓存命中率  ✓
- C. 语义缓存不需要向量数据库
- D. 精确缓存只适用于图像，语义缓存适用于文本

**解析**: 精确缓存仅在完全相同的查询时命中（"明天天气怎样"≠"明天的天气如何"）。语义缓存：将查询嵌入为向量，在向量库中检索相似历史查询（相似度 >0.95），若找到则直接返回缓存响应。GPTCache 等框架将命中率从精确缓存的 <5% 提升到 20-40%，显著降低 API 调用成本。

### Q2
**问题**: 提示词压缩技术（如 LLMLingua）的工作原理是什么？

- A. 删除提示词中的标点符号和停用词
- B. 用小型模型（如 GPT-2）计算每个 token 的困惑度，删除信息量低的 token，保留高信息密度的核心内容  ✓
- C. 将长提示词摘要为短版本
- D. 将提示词转换为更紧凑的编程语言

**解析**: LLMLingua 用一个小型语言模型（Phi-2等）对提示词中每个 token 计算条件概率，困惑度低的 token（容易预测/信息量低）被删除，困惑度高的 token（关键信息）被保留。可将提示词压缩到原始的 20-50%，在 RAG 场景下压缩检索结果，同时保持较高的响应质量。

### Q3
**问题**: LLM 路由（Model Routing）策略如何降低成本？

- A. 将所有请求路由到最便宜的模型
- B. 基于查询复杂度（如困惑度、长度、任务类型）自动将简单任务发送到小模型，复杂任务发送到大模型  ✓
- C. 在不同时段路由到不同区域的数据中心
- D. 路由到延迟最低的模型实例

**解析**: "今天星期几" 这类简单问题 GPT-3.5（$0.002/1K tokens）足以完美回答，无需 GPT-4（$0.06/1K tokens，贵 30 倍）。路由策略：(1) 规则路由（关键词/长度阈值）；(2) 分类模型路由（训练小分类器判断任务类型）；(3) 级联路由（先发给小模型，若置信度低再发大模型）。实践中可将 50-80% 的请求路由到小模型，整体成本降低 60-80%。
